# 城市末端配送模拟 · 到货签收与代收款项交接台

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 业务闭环

1. **订单登记**：应收款、温区（常温/冷藏/冷冻）与温度上限、原骑手、站点、返仓点。
2. **到货签收**：录入实测温度、现金、电子支付与签收人。
   - 实测温度超过温区上限即**超温**，只能**拒收并生成返仓单**，签收按钮禁用。
   - 现金 + 电子支付必须与应收**对平**；差额未挂账不得签收。
   - 签收即留**付款快照**（应收/现金/电子/温度/签收人/原因/时间）。
   - **复签**必须填写原因，自动追加 v2、v3… 新版本，旧版本不可修改。
3. **骑手交班**：按班次汇总应收现金/电子，与实收逐项核对。
   - 支付必须对平；存在差额时须勾选**挂账**并填写说明，否则不能交班。
   - 交班记录留痕，冲突台持续跟踪挂账差额。
4. **返仓单**：超温拒收自动生成，**占用原骑手和站点容量**；未关闭前不得释放容量。关闭后容量释放，订单保留拒收历史（重新派送需另登记）。
5. **冲突台**：刷新后订单、款项、返仓单、版本一致性校验，冲突统一列出**订单、骑手、差额、温度**（超温未处理、返仓待关闭、款项差额、容量超限）。

数据保存在浏览器 localStorage，刷新后订单、款项、返仓单与版本保持一致；结构校验失败自动回退演示数据。

## 分层结构

```
src/
  data/        数据层：types.ts 领域模型 / seed.ts 种子 / storage.ts 持久化与结构校验
  rules/       规则层：纯函数，无 Vue、无副作用（对平、超温、容量、冲突检测）
  store.ts     Pinia：数据 × 规则的唯一桥梁
  components/  界面层：登记台 / 签收台 / 交班台 / 返仓台 / 冲突台
  App.vue      纯布局组装
```
